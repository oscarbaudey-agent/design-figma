# Figma constraints for the converter

Researched 2026-10-24. No Figma file was touched: the Figma MCP in this session is not signed in (only `authenticate` tools were present), so nothing below was run against a live file. Every claim is tagged with its source, or "unverified".

Source keys:
- SKILLS = the `figma/skills/` folder of the official Figma plugin for Claude Code (plugin docs, v `figma_prod@2_2_157`)
- DTS = `SKILLS/figma-use/references/plugin-api-standalone.d.ts` (the plugin's bundled typings, the API surface use_figma runs against)
- MCPDOC = https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/
- FORUM = https://forum.figma.com/ask-the-community-7/mcp-loadfontasync-fails-for-locally-installed-fonts-52313

## Top blocker

**Local fonts do not work through `use_figma`.** Figma staff (FORUM, 2026-03-31): "Server-side tools like Figma MCP server can only access fonts that are uploaded to Figma's servers." Supported: Google and Apple fonts that ship with Figma, plus fonts uploaded to an organisation or team (Organization/Enterprise plans). Not supported: fonts installed on this Mac via Figma Font Helper / the desktop app. Reported symptoms: `listAvailableFontsAsync()` omits the font, `loadFontAsync()` throws, and `appendChild`/`createInstance` then fail with "unloaded font".

Denim INK and Circular XX Mono are installed locally only, so on current evidence the builder cannot set them as text fonts. This is a limitation, not a bug, per staff. Not tested here (no MCP session), so confirm in step 1 of the build with `listAvailableFontsAsync()` filtered on "Denim" and "Circular". Options for the owner to decide (see Implications): upload the fonts to a Figma org/team font library (needs Organization or Enterprise plan; unknown which plan the account has), or substitute.

## 1. Slides

Source: SKILLS/figma-use-slides/SKILL.md, references/slide-lifecycle.md, slide-grid.md, slide-gotchas.md, slide-content.md.

- **Create a slide:** `const s = figma.createSlide()` appends to the last row; `figma.createSlide(row, col)` places it. A fresh Slides file has an empty grid (`getSlideGrid()` returns `[]`), and the first `createSlide()` creates row 0. `createSlide` returns a `SlideNode` (extends `BaseFrameMixin`, DTS line ~9762), so it has `fills`, `children`, `resize`, `clone`, `findAllWithCriteria`.
- **Background:** set `slide.fills = [{type:"SOLID", color:{r,g,b}, opacity?}]`, or a gradient / image paint array, on the SLIDE node itself. Do not touch `.fills` on `SLIDE_GRID` or `SLIDE_ROW` (opaque, throws). Slide size is 1920x1080 by default (slide-content.md "Positioning within slides"; read `slide.width/height` back to confirm).
- **appendChild before x/y (critical):** new nodes are silently auto-parented to a hidden slide context at absolute (240,240). Setting `x`/`y` before the final `appendChild` stores them against that origin, and the node lands at (intended-240, intended-240). Intermittent, so a passing test proves nothing. Rule: `parent.appendChild(node)` first, then `resize`, fills, then `x`/`y`, at every nesting level. Never compensate by adding 240. Drift check: read `node.x` back and compare to what was written. Helper pattern in slide-gotchas.md ("Position after appendChild").
- **Many slides per call:** yes. SKILLS/figma-use/SKILL.md section 6: "Building 3-5 new slides in one call is safe", and one edit applied across every slide in one call is fine. The docs recommend 3-5 slides per `use_figma` call. The relevant limit is described as "complexity per slide, not total nodes across slides".
- **Per-call limits (code size, runtime, timeout):** **unverified.** No document in SKILLS or on developers.figma.com gives a number. The only hard numbers found: write tools are exempt from the MCP rate limits (SKILLS README line 6), and read tools are capped per plan (6 calls/month on Starter or View/Collab seats; 10/min Pro, 15/min Org, 20/min Enterprise, via a web search summary of Figma's help text). Plan on small calls (3-5 slides, hundreds of nodes) and have the builder measure: first call with 1 slide, then raise until a failure, and record the ceiling here.
- **Error handling:** every `use_figma` error carries `safeToRetryWithoutCanvasRead`. If true, fix and retry; if false, read the canvas first (SKILL.md rule 14). So build each slide so a re-run does not duplicate: name the slide `NNN <label>` and have the script look up an existing slide with that name and clear its children before building.
- **Other slide rules:** `figma.createPage()` throws in Slides. `get_metadata` does not work on Slides files; validate with read-only `use_figma` scripts. `console.log` is not returned; only `return` values are. Do not call `closePlugin()`; scripts are wrapped in an async context. `return` all created node ids. Section (row) name is settable via `figma.currentPage.children.find(c=>c.type==="SLIDE_GRID").children[i].name`. State does not persist across calls, so pass ids as string literals.

## 2. Images

- **Official path is `upload_assets`, not the plugin API.** SKILLS/figma-use/references/api-reference.md "Images": "`upload_assets` is the ONLY supported way to upload images into a Figma file... Do NOT use `figma.createImage()` or `figma.createImageAsync()` from inside `use_figma`... `use_figma` has no network access (so `createImageAsync(src)` cannot fetch URLs)." MCPDOC: `upload_assets` accepts PNG, JPG, GIF, WebP and SVG, up to 10 MB each, up to 60 files per call, remote server only, works in Slides.
- **How it works:** `upload_assets({fileKey, count, nodeIds?, scaleMode})` returns single-use `submitUrl`s; POST raw bytes (multipart/form-data, field `file`; the filename becomes the layer name). Pass `nodeIds` (one per upload) to set each image as a fill on an existing node (so the builder first creates a rectangle per image, then uploads into it); omit `nodeIds` and each image lands as a new layer. The response contains an `imageHash`. (api-reference.md lines 264-286; slide-content.md "Adding images to a slide".)
- **SVG uploads become editable vector layers, not image fills** (MCPDOC). That is a second route for our `svg` IR nodes besides `createNodeFromSvg`.
- **Reusing a hash:** documented as legitimate: `node.fills = [{type:'IMAGE', scaleMode:'FILL', imageHash:'<hash>'}]` in a later `use_figma` call, once the image is in the file (api-reference.md "Re-using an existing imageHash"). `figma.getImageByHash(hash)` returns the `Image` or null (DTS line ~934). So the builder need not use `setSharedPluginData`; store the `content-hash -> imageHash` map outside Figma (in figma-work) and verify with `getImageByHash` at the start of each call. Whether an `imageHash` stays valid when the same bytes are uploaded twice (dedupe) is unverified.
- **Size limits:** `createImage` doc (DTS line ~928): PNG, JPEG or GIF only; "maximum size of 4096 pixels in width and height"; invalid images throw. Same 4096x4096 on https://developers.figma.com/docs/plugins/working-with-images/. Whether `upload_assets` shares the 4096 cap, or only the 10 MB file cap, is unverified. Downscale any asset above 4096 on either side to be safe.
- **Plugin-API routes (unsupported for agents, listed for completeness):** `figma.createImage(Uint8Array)` (sync, DTS ~930); `figma.createImageAsync(url)` (async; CORS can block; no network inside use_figma per SKILLS); `figma.base64Decode(str)` / `figma.base64Encode(bytes)` exist (DTS ~1064-1070, api-reference.md "Utilities"). Embedding base64 in the script would count against the unknown code-size limit and is "not durable" per SKILLS. Do not use.
- **Rasters of canvas / unrepresentable elements** ("raster:<why>" nodes) go through the same `upload_assets` path as PNG.

## 3. Fonts

- **Style naming:** call `await figma.listAvailableFontsAsync()` and use the exact `{family, style}` it returns; never guess (`"Semi Bold"` not `"SemiBold"`) (SKILL.md rule 8; gotchas.md "Font style names are file-dependent"). Every font must be loaded with `await figma.loadFontAsync(...)` before any text change (characters, fontSize, fontName, even `appendChild` into a node holding that font).
- **Variable axes ARE settable, in the bundled typings.** DTS lines ~1835-1900: `FontName` has `variationSettings?: {[axisTag]: number}` ("mirroring CSS font-variation-settings"). Set with `text.fontName = {family, style, variationSettings:{wght:700, wdth:150}}` or per range with `setRangeFontName(start, end, {family, style?, variationSettings})`. Omitted axes keep the named instance's value; setting an axis the family lacks throws. `figma.getFontFamilyVariationAxes(family)` returns the tags (`["wght","wdth"]`) or `null` for a static family. `loadFontAsync({family})` with no `style` loads every style of the family and ignores `variationSettings`. Reading `fontName` on a variable font returns every axis; returns `figma.mixed` if ranges differ. Public confirmation: https://developers.figma.com/docs/plugins/api/FontName/. This maps directly onto our IR `variation: {wght, wdth}`. Not tested live; `wdth` outside the font's declared range (Denim INK 50-200 declared) behaviour unverified.
- **Local variable fonts:** the above only helps if the family is visible to `use_figma`; see Top blocker. For Denim INK there is no evidence either way on how Figma names its instances (the named instances come from the font's `fvar` table); read them with `listAvailableFontsAsync` once the font is available, and rely on `variationSettings` rather than style names.
- **Missing font, browser vs desktop:** FORUM: through the MCP/`use_figma` (a remote server) local fonts fail to load whether or not the desktop app is open. In the desktop app UI, locally installed fonts show as "Installed by you" and render; in the browser, local fonts need Figma's font installer/agent and are not what `use_figma` sees. The thread did not test the browser app, so browser behaviour is unverified. DTS (~5034, ~5049) warns that a text node with a missing font is resized but does not re-layout until opened on a machine that has the font, so text boxes will be wrong-sized in any viewer that lacks the font. `figma.hasMissingFont` reports whether the document has missing fonts; use it as a post-build check.
- **Candidate substitute with a width axis (unverified in Figma):** Roboto Flex (Google Fonts, has `wght` and `wdth`) would let us keep a wdth 150 look if Denim INK cannot be loaded. Check with `getFontFamilyVariationAxes("Roboto Flex")`.

## 4. Vectors, gradients, corners, text features

- **`figma.createNodeFromSvg(svg): FrameNode`** (DTS ~922). Equivalent to the editor's SVG import; returns an editable frame at the SVG size. Always give the SVG a `viewBox` plus explicit `width`/`height`; resize afterwards with `frame.resize(w,h)` (children carry SCALE constraints) (gotchas.md ~1005-1010; plugin-api-patterns.md "SVG Import"). Appended-to-slide ordering rule applies: append first, then set x/y. Size limit, supported SVG features (filters, masks, clipPath, `<text>`, `<image>`, CSS in `<style>`, `currentColor`, gradients with `gradientTransform`) are **unverified**: the docs state none. The extractor already inlines computed fills/strokes, which is the right precaution. Test with the `oc-wordmark` and `oc-dots` SVGs first. If an SVG imports wrongly, fall back to a PNG raster node.
- **Linear gradient:** `{type:'GRADIENT_LINEAR', gradientStops:[{color:{r,g,b,a}, position}], gradientTransform:[[a,b,c],[d,e,f]]}` (plugin-api-patterns.md "Linear Gradient"; DTS GradientPaint ~2593). Note: stop colors take `a` in gradient stops (RGBA); solid paint colors take `{r,g,b}` with opacity on the paint. The matrix maps node-normalised coordinates (x/W, y/H, both 0..1) to gradient space, where the gradient runs along gx from 0 to 1. Evidence from the docs: `[[1,0,0],[0,1,0]]` is left-to-right and `[[0,1,0],[-1,0,1]]` is top-to-bottom; the second only works if `gx = 0*x + 1*y + 0 = y`, i.e. row 0 is the position along the gradient. (Whether it is node->gradient or the inverse is not stated; the two documented examples fit node->gradient, and the inverse reading would give bottom-to-top for the second. Validate with one screenshot before trusting.)

  **CSS angle to matrix (derived, not from Figma docs).** CSS `linear-gradient(<theta>deg, ...)`: 0deg points up, 90deg right, clockwise. For a box W x H:
  ```
  dx = sin(theta);  dy = -cos(theta)            // unit direction in pixels, y down
  L  = |W*sin(theta)| + |H*cos(theta)|          // CSS gradient line length
  a  =  W*dx / L
  b  =  H*dy / L
  c  =  0.5 - (a + b)/2
  nx = -dy; ny = dx                              // perpendicular, keeps the matrix invertible
  d  =  W*nx / L
  e  =  H*ny / L
  f  =  0.5 - (d + e)/2
  gradientTransform = [[a,b,c],[d,e,f]]
  ```
  Derivation: t = ((p - center) . d)/L + 0.5 with p = (W x, H y), expanded in normalised x,y. Checks: theta=90 gives `[[1,0,0],...]` (matches the doc's left-to-right); theta=180 on a square gives `[[0,1,0],[-1,0,1]]` (matches the doc's top-to-bottom exactly). For non-square boxes row 1 differs from the doc's constant but only affects the cross axis, which a linear gradient ignores. CSS stop positions map straight to `position` (0..1); stops given in px must be divided by L first. Multi-fill CSS backgrounds map to the `fills` array in reverse order (CSS lists top layer first, Figma `fills[0]` is the bottom).
- **Radial gradient:** `GRADIENT_RADIAL`, transform semantic per plugin-api-patterns.md: 2x3 affine, scale below 1 makes the gradient larger than the shape. Identity gives a circle/ellipse centred in the box reaching the edges at the midpoints (reasoning from the linear case; unverified). CSS `radial-gradient` default is farthest-corner, centred; mapping details unverified, so the extractor should record `at` position and `size` keyword and the builder should screenshot-test the first one it meets.
- **Per-corner radius:** `RectangleCornerMixin`: `topLeftRadius`, `topRightRadius`, `bottomRightRadius`, `bottomLeftRadius` (DTS ~6521). IR order is [tl,tr,br,bl], so it maps one-to-one. `cornerRadius` sets all four. Radii beyond half the shorter side are clamped by CSS but may not be clamped identically in Figma, so clamp in the builder. Elliptical CSS radii (`10px / 20px`) have no Figma equivalent; use the larger value or rasterise. Smoothing is `cornerSmoothing`, not needed.
- **Strokes:** `strokes=[{type:'SOLID',color}]`, `strokeWeight`, `strokeAlign` 'INSIDE'|'CENTER'|'OUTSIDE' (plugin-api-patterns.md "Strokes"). IR uses INSIDE, matching CSS `border` / `box-sizing:border-box`. Per-side borders: unverified here (`IndividualStrokesMixin` exists in DTS); extractor should only emit uniform strokes.
- **Text properties** (DTS ~3195-3215, ~3300-3320):
  - `letterSpacing = {unit:'PIXELS', value:n}` (also 'PERCENT'). Use PIXELS; the IR carries px. Per-range: `setRangeLetterSpacing(start,end,{unit,value})`.
  - `lineHeight = {unit:'PIXELS', value:n}` or `{unit:'PERCENT'}` or `{unit:'AUTO'}`. Use PIXELS from the IR `lineHeightPx`. Per-range `setRangeLineHeight`. Figma centres the line box like CSS does, but the first-line offset can differ slightly from the browser for tall fonts; the pixel diff will show it.
  - `textAutoResize`: `'NONE' | 'WIDTH_AND_HEIGHT' | 'HEIGHT' | 'TRUNCATE'`. Default is WIDTH_AND_HEIGHT (hugs on both axes, ignores FILL). Mapping from IR: `wrap:false` -> `WIDTH_AND_HEIGHT`; `wrap:true` -> `resize(w, h)` then `textAutoResize='HEIGHT'`, or `'NONE'` when the box height must be held exactly. Call `resize()` BEFORE setting sizing modes (it resets them to FIXED) (SKILL.md rules 12c; gotchas.md ~672). Check `node.width > 0` afterwards.
  - `textCase`: `'ORIGINAL'|'UPPER'|'LOWER'|'TITLE'|'SMALL_CAPS'|'SMALL_CAPS_FORCED'` (settable per range with `setRangeTextCase`). The IR already applies text-transform to `characters`, so leave `textCase` ORIGINAL; applying both would be harmless for UPPER but wrong for TITLE.
  - Alignment: `textAlignHorizontal` 'LEFT'|'CENTER'|'RIGHT'|'JUSTIFIED', `textAlignVertical`.
  - Runs: `setRangeFontName`, `setRangeFontSize`, `setRangeFills`, `setRangeTextDecoration`, `setRangeLetterSpacing`, `setRangeLineHeight` take (start, end, value). Fonts for every range must be loaded first. `setRangeFills` colours need `{r,g,b}` 0-1; run opacity goes on the paint's `opacity`.
  - Colours everywhere are 0-1 floats, not 0-255.
  - Also available if needed: `textWrapStyle` ('AUTO'|'BALANCE'|'PRETTY', DTS ~3214), `paragraphSpacing`, `leadingTrim`.
- **Node opacity and clipping:** `node.opacity` 0..1; `frame.clipsContent`. Rects with `clipsContent` become frames in Figma (rectangles have no children); use `createFrame` for those and `createRectangle` otherwise.

## 5. Screenshots (needed for the pixel diff)

- **`get_screenshot`** (MCPDOC): supported in Design, FigJam and Slides files; one node per call; **PNG only**; returns a URL, or inline base64 if `enableBase64Response` is set; always re-renders. Output pixel dimensions and any size cap are **unverified** (not documented). It takes a `nodeId`, so on Slides pass the SLIDE node id returned by `createSlide`. `get_metadata` does not work on Slides, but `get_screenshot` does (SKILLS figma-use-slides SKILL.md "Inspecting Slides Files").
- **Inline alternative:** inside `use_figma`, `await slide.screenshot({scale})` returns a PNG in the tool response (DTS `ScreenshotOptions` ~10271; SKILL.md "node.screenshot"). Default scale 0.5, and the default is capped so the largest dimension is at most 1024 px (so a 1920x1080 slide returns about 1024x576). An explicit `{scale: N}` bypasses the cap, so `scale: 1` should return 1920x1080 and is what the diff needs (not yet measured). `contentsOnly:false` includes overlapping sibling content.
- **For the diff:** the MCP returns an image to the model, not a file on disk, unless the URL form is fetchable. Plan for fetching the returned URL with curl (unverified that it is unauthenticated), or `enableBase64Response` and decoding. Compare against `ref/slide-NNN.png` at 1920x1080; if Figma returns a different size, resample the reference to the same size with the same filter and set the threshold on that, and say so in the report. The harness screenshot rendering uses Figma's renderer with the fonts available on Figma's servers, which is the same constraint as the Top blocker: text in a missing font will be drawn in a fallback, and the diff will blame the font, not the builder.
- **Known risk for the diff:** an early or stale render of images or fonts can occur; take the screenshot in a later call than the one that built the slide.

## Implications for the builder

1. **Resolve the font question before anything else.** First builder call: list fonts and check Denim INK and Circular XX Mono. If absent (expected), stop and put the choice to the owner: (a) upload the font files to a Figma org/team library (needs Organization/Enterprise plan), (b) substitute with named fallbacks (Roboto Flex for the wdth axis; a Google mono for Circular XX Mono) and store the intended font in each text node's name and `setPluginData`, or (c) convert text to vector (loses editable text, which defeats D-001). Do not silently substitute.
2. **Text boxes will drift if the font is substituted.** Hold the IR box: `resize(w,h)` and use `textAutoResize='NONE'`, or `HEIGHT` for wrapping text; for `wrap:false` use `WIDTH_AND_HEIGHT` and compare the resulting width against the IR `w`.
3. **Always parent first, position last,** at every level, with the helper functions from slide-gotchas.md. After each slide, return `{node.name, intended x/y, actual x/y}` and fail on any difference.
4. **Build 3-5 slides per call, idempotently** (look up a slide by name, wipe its children, rebuild). Start with a 1-slide call to find the real runtime/size ceiling, and write the measured numbers into this file.
5. **Images:** use `upload_assets` only. Create a rectangle per image first, then upload with `nodeIds` and `scaleMode`. Keep a content-hash to `imageHash` map in figma-work, and check `figma.getImageByHash` before re-uploading. Downscale anything over 4096 px. Never put image bytes in the script.
6. **Variable font axes:** apply `variationSettings:{wght, wdth}` from the IR run's `variation` through `setRangeFontName`; first call `getFontFamilyVariationAxes(family)` and skip axes the family lacks to avoid throws.
7. **SVG:** try `createNodeFromSvg` (with `viewBox`, `width`, `height`), append, then position and `resize`. On a visibly wrong result, fall back to a "raster:" PNG and report it.
8. **Gradients:** compute `gradientTransform` with the formula in section 4 and prove it on slide 17 (index 16) before trusting it. Stop colours need `a`; the IR opacity maps to that.
9. **Per-corner radius:** use the four `*Radius` properties in order tl, tr, br, bl; frames for clipping content, rectangles otherwise.
10. **Diff harness:** screenshot with `slide.screenshot({scale:1})` or `get_screenshot` on the SLIDE id; measure the real output size on the first slide and record it here. Expect the font substitution to dominate the score until the Top blocker is settled, so score text areas and non-text areas separately.
11. **Unverified items to measure on the first live run:** use_figma code-size and runtime ceilings; whether `upload_assets` enforces 4096 px; `get_screenshot` output size; whether `wdth` 150 renders; SVG feature coverage; radial gradient mapping. Update this file with each measured answer.

## Local plugin route (D-005)

Researched 2026-10-24. Sources: DTS = figma-use/references/plugin-api-standalone.d.ts; SLIDES = figma-use-slides skill; DOCS = developers.figma.com pages fetched today (manifest, making-network-requests, how-plugins-run, creating-ui, figma-showui, api/figma, working-with-text); HELP = help.figma.com "Access local fonts". Nothing here was run in Figma yet; "unverified" means no source confirmed it.

### 1. Slides support, manifest, import
- **editorType:** DOCS manifest lists `figma`, `figjam`, `dev`, `slides`, `buzz`. So `"editorType": ["slides"]` is the documented value. Only `["figjam","dev"]` is flagged unsupported.
- **Dev plugins run in Slides:** the docs say nothing explicit. Evidence for: `slides` is a valid editorType, and `figma.createSlide` is declared in DTS ("only available in Figma Slides"). A dev plugin running in a Slides file is therefore expected to work, but is **unverified until first run**.
- **Import and run (desktop):** DOCS quickstart only confirms **Plugins > Development > [plugin name]** for running, and **Plugins > Development > New plugin** for scaffolding. The import step is **Plugins > Development > Import plugin from manifest...**, then pick `manifest.json`. That menu label is from memory and was not on any fetched page: **unverified**. Open a Slides file (`figma.com/slides/...`) first, then run it from the same Development submenu. Whether the Development submenu appears inside a Slides file is unverified.
- **documentAccess:** DOCS says the only value is `"dynamic-page"`, required for new plugins.
- **permissions:** none needed (only currentuser, activeusers, fileusers, payments, teamlibrary exist).

### 2. networkAccess to localhost
- DOCS manifest: `devAllowedDomains` is for local/dev servers used only in development; example form `"http://localhost:3000"`. Schemes http/https/ws/wss are allowed in patterns, a port goes after the host. `reasoning` is required when `allowedDomains` contains `*` or localhost. DOCS prose does not require it for `devAllowedDomains`, but the interface lists `devAllowedDomains` without `?`; keeping `reasoning` in the manifest is harmless and recommended.
- Plain http on localhost works as a dev domain per the documented example (config-wise). Actual fetch from the iframe on desktop is **unverified**.
- CORS: DOCS says plugin iframes have a `null` origin, so the server must send `Access-Control-Allow-Origin: *`. Also answer `OPTIONS` preflight (needed for POST with `Content-Type: application/json` or `image/png`): CORS preflight handling is **unverified in the docs**, but required by browser rules. Allow headers `Content-Type` and methods `GET, POST, OPTIONS`.
- Blocked domains give a CSP error. `allowedDomains: ["none"]` plus `devAllowedDomains` is the contract's combination and is consistent with DOCS.
- `fetch` lives in the UI iframe only; the sandbox has no fetch (DOCS how-plugins-run). Matches the contract (ui.html does all HTTP).

### 3. Local fonts
- DOCS: `listAvailableFontsAsync` "should be the same list as the one you'd see if you manually used the font picker" (DTS ~848). HELP: in the desktop app, fonts installed on the computer are detected automatically (built-in font installer); the browser needs FigmaAgent. HELP does not say plugins see them. Inference: the picker includes local fonts, so the plugin list should too. **Unverified until the probe job runs.** This is exactly what the `probe` job kind is for: check Denim INK and Circular XX Mono in the result.
- Requirement: font installed before the app starts, or restart Figma desktop after installing (HELP says restart after installing the font installer; restart after installing a font is the safe assumption, unverified).
- A font that is not installed is "missing", not just unloaded: check `text.hasMissingFont`; load with `figma.loadFontAsync` before any text change (DOCS working-with-text).
- Variable fonts: `figma.getFontFamilyVariationAxes(family)` returns `string[] | null` (DTS 914). Set `fontName = {family, style, variationSettings:{wght, wdth}}`; an omitted axis keeps the named instance default, an unknown tag **throws**, omitting `style` lets Figma pick the nearest named instance (DTS ~1856, ~7373; DOCS). Keys must match the axis tags returned. `fontName` reads back `figma.mixed` when variation differs across ranges. Whether a local variable font (Denim INK, wdth axis) exposes axes through this API on desktop is **unverified**; the probe `axes` field answers it. Loading by family only (`loadFontAsync({family})`) loads all styles and works for variable families (DOCS).

### 4. Slides API
- `figma.createSlide(row?, col?)` returns SlideNode; default appends to the end of the last row (DTS 501-510). A fresh file has an empty grid and the first call creates row 0 (SLIDES slide-grid.md).
- Grid: DOCS api/figma marks `getSlideGrid` / `setSlideGrid` **deprecated**; use `figma.getCanvasGrid(): SceneNode[][]` and `figma.setCanvasGrid(SceneNode[][])` (DTS 1087, 1110). Existing slides must all be present when setting. CONTRACT-relevant: build ordering with `getCanvasGrid`, falling back to `getSlideGrid`. SLIDE_GRID and SLIDE_ROW are opaque (no fills); only SLIDE has frame props (SLIDES SKILL.md rule 3).
- Size: 1920x1080 (SLIDES slide-gotchas.md line 250, `SLIDE_W/SLIDE_H`). Whether the size is changeable is unverified.
- Background: set `slide.fills = [{type:'SOLID', color:{r,g,b}}]` on the SLIDE node (slide-gotchas.md 198-202). Image or gradient fills on a SLIDE: expected to work as it is a BaseFrameMixin, **unverified**.
- Export: `slide.exportAsync({format:'PNG', constraint:{type:'SCALE', value:1}})` returns `Uint8Array` (DTS 2923, 6629; scale 1 is the default). Nothing in the sources says SLIDE exports are blocked, but **unverified on SLIDE**. Do not use `node.screenshot()` (DTS 10271): that is a use_figma harness helper, capped at 1024 px by default.
- Slide tagging: `setSharedPluginData('designfigma','index', ...)` exists on all nodes (DTS 4154); no slide-specific caveat found. Unverified on SLIDE. Fallback: `setPluginData`.
- `figma.createImage(bytes)`: PNG, JPEG or GIF only; max 4096 px width and height; invalid images throw (DTS 928). Maximum byte size not documented. WebP is not supported: the server must convert any webp to png/jpg. Fills use `{type:'IMAGE', imageHash, scaleMode}`.
- `figma.createNodeFromSvg(svg)` returns a FrameNode (DTS 922). Slides availability: SLIDES lists Frame, Vector, BooleanOperation etc. as available and does not list createNodeFromSvg either way: **unverified**. Test on first SVG node.
- Node types blocked in Slides: Sticky, Connector, ShapeWithText, CodeBlock, Webpage, Page; `figma.createPage` throws (figma-use SKILL.md 84-88).

### 5. Sandbox and messaging limits
- DOCS how-plugins-run: ES2020 and beyond is supported (optional chaining, nullish coalescing, logical assignment), with Map, Set, Promise, JSON, structuredClone. A `bun build --target=browser` output at ES2020 should load; keep no top-level await and avoid ES2022+ class static blocks (**unverified** beyond the ES2020 statement). No eval is needed.
- The sandbox has no fetch, XHR, DOM, or `setTimeout` per DOCS (this contradicts nothing in the contract, but code.ts must not use timers; drive timing from ui.html). Note `closePlugin` cancels timers, so DOCS implies setTimeout/setInterval exist in some form: conflicting, treat as **unverified** and keep timers in the UI.
- postMessage: DOCS creating-ui: messages are serialised like JSON; `Uint8Array` is supported, but **no ArrayBuffer, Blob or other typed arrays**. So images must be sent as `Uint8Array` (as in the contract), never `.buffer`. Message size limit: **not documented, unverified**. Mitigation: the server caps images at 4096 px; if a single message fails, send per-image messages (the contract already does `images` per build; if a limit shows up, split into one message per ref).
- Messages from code to UI queue until the iframe has loaded.
- Plugin runtime limit: not documented. A plugin runs until `figma.closePlugin()` is called or the user cancels; it shows a "Running <name>" toast (DOCS).

### 6. Keeping the UI open and polling
- `figma.showUI(__html__, {visible:false})` is allowed: `visible` defaults to true, and `figma.ui.show()` / `hide()` toggle it (DOCS figma-showui). Whether a hidden iframe is throttled by Electron is **unverified**; use a visible small window (e.g. 320x120) to be safe.
- Polling: nothing forbids a never-closing plugin; DOCS says that if `closePlugin` is not called it "runs indefinitely". The Figma UI iframe can use `setInterval`/`fetch` normally (browser context). Throttling when Figma is in the background is unverified.
- Closing: the user cancelling the plugin makes Figma call `closePlugin`. Calling `figma.showUI` again closes the previous UI. `closePlugin` also closes the UI and cancels timers. There is no documented method to close only the UI.
- Do not call `figma.closePlugin()` at the end of a job; only on a user close or a `quit` job.
- `figma.ui.onmessage` and `figma.ui.postMessage` are the channel. `figma.notify` is available in Slides: unverified.
